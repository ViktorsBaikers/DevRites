# Harness adapter compliance

DevRites drives more than one agent runtime from a single `devrites-engine`
binary, but the runtimes do not expose identical enforcement surfaces. This page
states — per surface — whether each supported harness enforces it natively,
through an adapter, or only by instruction the model may ignore. It is the honest
answer to "does DevRites work the same on Codex as on Claude Code?"

Host facts live in `engine/internal/harness/hosts.json`; update that descriptor before adding another host.

The table below is **generated**. The single source of truth is the frozen matrix
in `engine/internal/harness/compliance.go`; regenerate this block with:

```sh
devrites-engine harness-matrix          # print the block
```

CI runs `devrites-engine harness-matrix --check docs/harness-compliance.md`, so
the table and the code can never silently drift apart.
