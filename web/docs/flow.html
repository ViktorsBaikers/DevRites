Flow

Every feature walks the same path. Each phase reads the previous phase's files and writes its own, so the build can survive a cleared context window or a hand-off to a fresh agent.

Feature lifecycle

1spec
2define
3build
4prove
5polish
6review
7seal
  1. SpecDeep read of the codebase before a line is written: placement, what the feature resolves, gaps closed with options, design references. /rite-spec → spec.md, references/
  2. DefineThe approved spec becomes a plan and vertical task slices, each tagged HITL or AFK with a checkpoint gate. /rite-define → plan.md, tasks.md, state.md
  3. BuildImplement exactly one vertical slice, then stop with evidence. HITL slices pause before code is written. /rite-build → code, evidence.md, touched-files.md
  4. ProveTests, build, runtime, and browser proof of the finished feature. Claims get backed by output. /rite-prove → evidence.md, browser-evidence.md
  5. PolishBehavior-preserving cleanup first, then UI polish against the design system. /rite-polish → polish-report.md
  6. ReviewIndependent fresh-context reviewers check the diff against the spec and the standards, in parallel. /rite-review → review.md
  7. SealFinal GO or NO-GO. Walk acceptance, fan out reviewers, and demand a typed GO before any irreversible git. /rite-seal → seal.md → commit · push · tag

Spec Drift Guard

If implementation reveals the plan is wrong, the build does not push on. The Spec Drift Guard stops, records the drift, asks you when product behavior changes, and routes through plan repair before resuming.

/rite-build # slice 3/5 ⚠ drift the auth model assumes sessions; spec needs stateless tokens → recorded to drift.md, build paused /rite-plan repair # reslice around the corrected model /rite-build # resume from the repaired plan
The point A wrong turn caught at slice 3 costs one repair. The same wrong turn caught at seal costs the whole feature. The guard makes the cheap moment the default.

Run modes

Same workflow, two postures. Slices are tagged per mode, so you decide how much the agent does on its own.

HITL — human in the loop

Default. Risky slices pause before code is written, at a typed checkpoint that escalates through advisory, validating, blocking, and escalating. Answer once with /rite-resolve <qid> "<answer>" and the build resumes.

AFK — away from keyboard

Drop a .devrites/AFK file in the project. AFK slices run unattended; discretionary pauses downgrade to advisory notes in questions.md so the loop keeps moving.

AFK never silently accepts risk Destructive migrations, auth and authz changes, public-API breaks, and red tests, types, or lint always pause, regardless of mode. Optional max_slices caps the run; optional notify pings your phone on a pause.
