Architecture

DevRites is a distributed but coordinated set of project-local Claude Code skills. Each phase is its own skill; none is a monolith. The pieces share one thing: state on disk under .devrites/.

Layers

LayerWhat lives here
Phase commands
rite-*		The seven workflow phases plus utilities, each a public, independently invokable skill.
Internal specialists
devrites-*		Model-invoked skills (interview, source-driven, doubt, frontend-craft, browser-proof, debug-recovery, api-interface, audit) that fire when a phase needs them.
Review agentsEight fresh-context reviewers spawned by /rite-seal and the doubt loop. Each reads the diff cold.
Persistent state
.devrites/		The per-feature Markdown workspace. The single source of truth between phases and across cleared contexts.
Engineering rules
.claude/rules/		Stack-agnostic rules: one always-on core.md plus fifteen on-demand files loaded by the phase that needs them (style, patterns, error handling, testing, code review, security, perf, and more).
Install & manifestinstall.sh records every written file in .claude/devrites.manifest; uninstall.sh removes exactly those and leaves .devrites/work/ untouched.

Design rationale

Why distributed skills, not one /engine

A single mega-command would load everything on every call and hide the workflow behind one opaque entry point. Separate phase skills stay small, stay discoverable from /rite, and each loads only the rules and references it actually needs. The workflow is legible because the commands map to it one to one.

Why rite-* names

Short, memorable, and brand-aligned — "rites" are disciplined, ordered steps. They are also collision-free: built-in and bundled Claude Code commands include /plan, /review, /run, /verify, /init, /compact, and /debug. The rite- prefix avoids all of them.

Why a thin menu skill, not a mega-router

/rite is a pure router: it shows the menu and suggests the next command, but it does not execute a phase or read state. That keeps every phase skill independently invokable by muscle memory (/rite-build) without forcing everything through one dispatcher.

Why internal skills exist

Specialists like devrites-doubt and devrites-frontend-craft are model-invoked, so they fire automatically at the right moment without cluttering the menu. The phase you run stays simple; the depth shows up only when the work calls for it.
