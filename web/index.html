The problem

Your agent writes plausible code, then says it's done.

Plausible is not correct. A wrong turn three steps back costs you a day. "Done" with no tests, a half-finished migration, and an auth change you never approved costs you trust. DevRites makes the agent work the way a careful engineer does: one slice at a time, decisions recorded, the receipts written to disk where you can read them.

The workflow

Seven phases. One verified slice at a time.

Every feature walks the same path. Each phase reads the last one's files and writes its own, so nothing important lives only in a chat window you can lose.

01 · spec

Investigate, then write it down

Deep read of the codebase before a line is written. Placement, what it resolves, gaps closed with options.

/rite-spec → spec.md, references/

02 · define

Slice the plan

The approved spec becomes a plan and vertical task slices, each tagged HITL or AFK with a gate.

/rite-define → plan.md, tasks.md

03 · build

One slice, then stop

Implement exactly one vertical slice and stop with evidence. The Spec Drift Guard catches a wrong plan mid-build.

/rite-build → code, evidence.md

04 · prove

Show the receipts

Tests, build, runtime, and browser proof of the finished feature. Claims get backed by output.

/rite-prove → browser-evidence.md

05 · polish

Tidy without breaking

Behavior-preserving cleanup first, then UI polish against the design system. Nothing silently changes.

/rite-polish → polish-report.md

06 · review

Fresh eyes, in parallel

Independent fresh-context reviewers check the diff against the spec and the standards, at once.

/rite-review → review.md

07 · seal

GO or NO-GO

Walk the acceptance criteria, fan out the reviewers, and demand a typed GO before any irreversible git.

/rite-seal → seal.md

On disk, not in chat

The paper trail survives /clear.

Every feature gets its own directory under .devrites/work/. When the context window fills and you clear it, the next agent reads these files and picks up exactly where the last one stopped. No summary, no re-explaining, no lost decisions.

spec.md holds the contract. decisions.md and assumptions.md hold the reasoning. evidence.md holds the proof. drift.md records where the plan was wrong and why.

Guardrails

It stops before it costs you.

Three mechanisms keep an unattended agent from doing the expensive, irreversible thing on its own.

Spec Drift Guard

When the build reveals the plan was wrong, it stops, records the drift, and routes through plan repair before resuming. The wrong turn never compounds.

⚠ drift detected · build paused
→ recorded to drift.md, asking before behavior changes

type-GO

No commit, push, or tag happens on a hunch. The final gate demands a literal typed confirmation before anything irreversible touches your git history.

seal: GO · awaiting confirmation
→ type GO to commit · push · tag

Reviewer fan-out

At seal, independent fresh-context reviewers read the diff in parallel. None of them is the agent that wrote the code, so none inherits its blind spots.

Two run modes

At the keyboard, or away from it.

Same workflow, two postures. You decide how much rope the agent gets per slice.

HITL

human-in-the-loop

Default. You're at the keyboard.

  • Risky slices pause before code is written, at a typed checkpoint.
  • Checkpoints escalate: advisory, validating, blocking, escalating.
  • Answer once with /rite-resolve and the build resumes.

AFK

away-from-keyboard

Drop .devrites/AFK in the project. It runs unattended.

  • Discretionary pauses downgrade to advisory notes so the loop keeps moving.
  • Destructive migrations, auth changes, public-API breaks, and red tests always pause.
  • Optional max_slices caps the run; notify pings your phone on a pause.
Install

One command. One project.

curl -fsSL https://devrites.com | bash

Prefer the Claude Code plugin? Skills and agents install partial via the plugin marketplace. Then run /rite-spec <feature> to begin.

  • →No global writes, ever. Installs into the target project; ~/.claude is refused.
  • →Every file is recorded in .claude/devrites.manifest. ./uninstall.sh removes exactly those.
  • →Your work is preserved. Feature data in .devrites/work/ is never touched by uninstall.
  • →Preview first with --dry-run. Pin a release with DEVRITES_REF=v1.0.4.
