The problem

Plausible is not correct.

A wrong turn three steps back costs you a day. "Done" with no tests, a half-finished migration, and an auth change you never approved costs you trust. DevRites makes the agent work the way a careful engineer does: one slice at a time, decisions recorded, the receipts written to disk where you can read them.

The workflow

Ten phases. One verified slice at a time.

Every feature walks the same path, grouped into three acts. Each phase reads the last one's files and writes its own, so nothing important lives only in a chat window you can lose.

01 · spec

Investigate, then write it down

Deep read of the codebase before a line is written. Placement, what it resolves, gaps closed with options and measurable acceptance criteria.

/rite-spec → spec.md, references/

02 · temper

Pressure-test the scope

Strategic review of the spec before planning: pick a scope mode, run a pre-mortem, and harden the contract so you build the right thing.

/rite-temper → strategy.md

03 · define

Slice the plan

The approved spec becomes a plan and vertical task slices, each tagged HITL or AFK with a gate. Every acceptance criterion maps to a slice.

/rite-define → plan.md, tasks.md

04 · vet

Review the plan before code

Engineering review of architecture, scope, and test coverage, confidence-banded. Writes the test plan the build will have to satisfy.

/rite-vet → eng-review.md, test-plan.md

05 · build

One slice, then stop

A fresh-context wright implements exactly one vertical slice, test-first, and stops with evidence. The Spec Drift Guard catches a wrong plan mid-build.

/rite-build → code, evidence.md

06 · prove

Show the receipts

Tests, build, types, lint, and browser proof of the finished feature, walked against each acceptance criterion. Claims get backed by output.

/rite-prove → browser-evidence.md

07 · polish

Tidy without breaking

Behavior-preserving cleanup first, then UI polish against the design system. Nothing silently changes; stale evidence is re-proven.

/rite-polish → polish-report.md

08 · review

Fresh eyes, in parallel

Independent fresh-context reviewers check the diff against the spec and the standards at once, none of them the agent that wrote the code.

/rite-review → review.md

09 · seal

GO or NO-GO

Walk the acceptance criteria against the evidence, fan out the reviewers, block on a Critical, and write the verdict before anything ships.

/rite-seal → seal.md

10 · ship

The irreversible step, gated

Only after a typed GO: the commit, push, and tag (or PR), then the workspace is archived and the active cursor cleared.

/rite-ship → ship.md

In a hurry? /rite-autocomplete drives the whole lifecycle unattended, pausing only at irreversible gates. Lost? /rite-status shows where the active feature stands; /rite opens the menu.

On disk, not in chat

The paper trail survives /clear.

Every feature gets its own directory under .devrites/work/. When the context window fills and you clear it, the next agent reads these files and picks up exactly where the last one stopped. No summary, no re-explaining, no lost decisions.

spec.md holds the contract. decisions.md and assumptions.md hold the reasoning. evidence.md holds the proof. drift.md records where the plan was wrong and why.

Tool-agnostic core

Drive it from anywhere.

The discipline lives in the .devrites/ files and a set of state scripts, not in the harness. A portable CLI and an MCP server expose the same deterministic gates to any agent, CI job, or human.

the devrites CLI · exit code is the gate
$ devrites orientworkspace digest
$ devrites readyexit 0 · ready
$ devrites evidence-freshexit 3 · stale
$ devrites acceptanceexit 0 · proven

A non-zero ready, evidence-fresh, or acceptance is a hard stop you can script into any agent loop or a pre-merge CI step.

the MCP server · dependency-free stdio
devrites_orientdevrites_ready devrites_evidence_freshdevrites_acceptance devrites_statusdevrites_active devrites_listdevrites_use

Register it in a project's .mcp.json and any MCP client can ask "is this feature ready to ship?" and get the same verdict /rite-seal would compute.

Two run modes

At the keyboard, or away from it.

Same workflow, two postures. You decide how much rope the agent gets per slice.

HITL

human-in-the-loop

Default. You're at the keyboard.

  • Risky slices pause before code is written, at a typed checkpoint.
  • Checkpoints escalate: advisory, validating, blocking, escalating.
  • Answer once with /rite-resolve and the build resumes.

AFK

away-from-keyboard

Drop .devrites/AFK in the project. It runs unattended.

  • Discretionary pauses downgrade to advisory notes so the loop keeps moving.
  • Destructive migrations, auth changes, public-API breaks, and red tests always pause.
  • Optional max_slices caps the run; notify pings your phone on a pause.
Questions

The skeptical-engineer FAQ.

Does DevRites send my code anywhere?

No. DevRites is a pack of local Markdown skills and shell scripts. Feature state lives in .devrites/ on disk in your repo. Nothing is uploaded. The only network call the site itself makes is to the public GitHub release API to show the latest version badge.

Does it touch my global ~/.claude?

Never. DevRites installs project-local and refuses a global target. Every file it writes is recorded in .claude/devrites.manifest, and uninstall removes exactly those. Your feature data in .devrites/work/ is never touched.

Which tools does it work with?

It is built for Claude Code as slash commands. The state core, a tool-agnostic devrites CLI and a dependency-free MCP server, lets Cursor, Codex, Gemini CLI, a CI job, or a human drive the same workflow against the same files.

How is it different from spec-kit, task-master, or BMAD?

Those orchestrate work across many agents. DevRites keeps the discipline in tool-agnostic files plus deterministic gates (ready, evidence-fresh, acceptance), so one verdict agrees whether it comes from the CLI, the MCP server, or /rite-seal.

Is it free?

Yes. DevRites is free and open source under the MIT license, on GitHub.

How do I install and uninstall?

Install with curl -fsSL https://devrites.com | bash (preview first with --dry-run). Uninstall with curl -fsSL https://devrites.com/remove | bash. It removes only what DevRites installed and preserves your feature data.
